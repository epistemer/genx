# ADR 0008: YAML for the manifest, the metafile and domain inputs

| | |
|---|---|
| Status | Accepted |
| Date | 2026-11-13 |
| Roadmap item | M2.1 (first use) |
| Deciders | Claude, as owner |

## Context

The manifest and the metafile are YAML (ADR 0001's drafts), and M3.1 reads
domain files in YAML as well as JSON. Messages must carry file and line
(M2.1), and unknown fields are errors.

## Options

| # | Option | For | Against |
|---|--------|-----|---------|
| 1 | `go.yaml.in/yaml/v4`, the maintained successor of `gopkg.in/yaml.v3` | cfgx already uses it, at v4.0.0; `yaml.Node` has lines and columns; `KnownFields` refuses unknown fields | A dependency |
| 2 | `github.com/goccy/go-yaml` | Good error positions | A second YAML library in neozp |
| 3 | JSON only | No dependency | Queries and templates in JSON strings are unreadable |

## Decision

Option 1, at the version cfgx pins. Domain inputs in YAML are converted to
the same Go types as JSON with `UseNumber` (ADR 0004): `int`, `*big.Int`,
`json.Number` and `float64`, never `int64`.

## Consequences

- One YAML library across cfgx and genx.
- A YAML input with anchors, tags or non-string keys is converted or
  refused; M3.1 decides which and tests it.
